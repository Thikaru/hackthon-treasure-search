# Unity グラフィック刷新 デザイン案（渋川からの挑戦状）

現状（React + Supabase の Web アプリ）を確認したうえでの提案です。
ゲームの流れ（宝の道標 → 場所ヒント → QR → 鍵のかかった宝箱の謎 → 獲得 → クリア証明）は変えず、見た目と演出だけを大きく上げる前提です。

---

## 0. 先に決めること：Unity をどこまで使うか

このゲームは「イベント当日にスマホのブラウザで QR を読んで、すぐ遊べる」ことが前提です。Unity にすると次の制約があります。

| 方式 | 良い点 | 問題 |
| --- | --- | --- |
| A. 全部 Unity WebGL | 見た目を全画面で統一できる | iPhone Safari で初回ロードが重い（10〜20MB）。カメラQR・実地図・日本語入力が Unity だと難しい |
| B. Unity ネイティブアプリ（iOS/Android） | 最高画質・カメラも安定 | 参加者にアプリのインストールが必要。イベント向きではない。ストア審査も要る |
| **C. ハイブリッド（推奨）** | React は残し、**演出が効く画面だけ Unity WebGL** を埋め込む。QR・地図・入力・Supabase は今のまま | Unity と React の橋渡し（`SendMessage` / `postMessage`）が必要 |

**推奨は C**。Unity で描くのは「タイトル」「地図（ジオラマ表示）」「宝箱を開ける」「お宝獲得」「コレクション棚」「クリア証明」の6場面。
ローディングは最初のタイトルで1回だけ（Brotli 圧縮で 8MB 以内を目標）にし、以降は同じ Unity インスタンスを使い回します。

## 1. デザインの方向性（3案）

### 案1：瀬戸内ジオラマ（推奨）
渋川海岸・王子ヶ岳・たまの湯を、**手のひらサイズのミニチュア模型**として 3D で作る。
少し上から見下ろすチルトシフト（ミニチュア写真風のボケ）、柔らかい影、波打ち際のアニメ。

- 強み：実在の場所が「宝の島」になる。地元の人ほど「ここだ！」と分かる。時間帯（昼・夕・夜）で光が変わる今のタイトルの考え方をそのまま 3D に拡張できる
- 雰囲気：『あつ森』や『Tiny Glade』のような、やさしい模型感
- 弱み：3 エリア分の模型制作が必要

### 案2：古地図と冒険手帳
羊皮紙・インク・蝋封の 2.5D 紙工作風。地図は手描きの宝の地図が広がり、謎は手帳に書き込まれる。

- 強み：「謎解き」との相性が最高。アセットが 2D 中心で軽い
- 弱み：実際の場所の分かりやすさが下がる。「グラフィックをかなり良く」の驚きは案1より小さい

### 案3：夜光の海
夜の海、夜光虫の青い光、星砂の粒子。宝箱やお宝が発光する幻想的な見た目。

- 強み：SNS に載せたくなる絵になる
- 弱み：昼間の屋外（砂浜の直射日光）でスマホ画面が見えにくい。イベントは日中が主なので不向き

**→ 案1を軸にして、謎・手帳まわりの UI だけ案2の「紙とインク」の質感を借りる**のを推します。
（日中の屋外で読みやすい明るさ、実在の場所が分かる、演出で驚かせる、の3つを満たすため）

## 2. 全体のルック（案1ベース）

| 項目 | 方針 |
| --- | --- |
| 画風 | ローポリ＋手塗り風テクスチャ。輪郭は描かず、面の色の差で形を見せる |
| カメラ | 斜め上 35° の見下ろし、FOV 狭め（ミニチュア感）。被写界深度で奥と手前をぼかす |
| 光 | 時間帯で3種（昼：白い日差しと青い影／夕：オレンジの逆光／夜：月光と街の灯り）。今の `useTimeOfDay` と同じ区切り |
| 色 | 今の配色を引き継ぐ：海 `#22406E`〜`#3A5C8F`、砂 `#D9B98A`／`#F1DDB8`、ブイの朱 `#D9472B`、獲得のコバルト `#1F4FB8`。ここに**金 `#E8B64A`**（お宝・獲得の光）を1色だけ足す |
| 文字 | 見出しは今の Zen Maru Gothic、本文 Noto Sans JP。Unity では TextMeshPro の SDF フォントにし、使う文字だけに絞って軽くする |
| UI の質感 | 謎のカードは「手帳の1ページ」：生成りの紙、少し荒れた縁、インクのにじみ。ボタンは丸く厚みのあるおもちゃ風（押すと沈む） |
| 音 | 波の環境音、ページをめくる音、鍵がカチッと鳴る音、獲得のチャイム（屋外なので短く・はっきり） |

## 3. 画面ごとの演出

### 3-1. タイトル
- 渋川海岸のジオラマがゆっくり回転。時間帯で光が変わる（今の実写3枚の代わり）
- 海面に光の反射、カモメ、遠くに瀬戸大橋のシルエット（今の夜景写真の名残を残す）
- タイトルロゴ「渋川からの挑戦状」は**封筒から手紙が出てくる**アニメで登場（＝挑戦状）。封蝋に宝箱のマーク
- 「はじめる」を押すと、カメラが模型に寄って地図画面へそのまま移る（画面の切り替えを感じさせない）

### 3-2. ホーム（地図）
- 地図の上半分を 3D ジオラマにする。エリア切替（砂浜／王子ヶ岳／たまの湯）は、**カメラが模型の上を飛んで移動**
- 宝箱を見つけた場所（`found`）に、**小さな宝箱が砂から跳ね出て**ピンになる。獲得済み（`acquired`）は宝箱が開いて金色に光る
- 道標をクリアした（`located`）けどまだ QR を読んでいないお宝は、地図には出さない仕様なので、代わりに**画面の端に「?」の霧**を漂わせ「まだ見つかっていない宝がある」気配だけ出す
- **実際の道案内は今の Leaflet 実地図を残す**（「実際の地図」ボタンで切替）。ジオラマは雰囲気用で、正確な道は実地図が担う
- 下部シートは手帳のページ。今の「前の内容が下がって次が下から出る」動きはそのまま、紙がめくれる表現に

### 3-3. 宝の道標（場所の謎）
- 道標＝**木の立て札**。画面上部に立て札があり、問題文がインクで書かれていく（タイプライター風に1文字ずつ）
- 正解すると立て札がくるっと回り、裏面に「場所のヒント（画像・説明）」が貼ってある
- 不正解は立て札がカタカタ揺れるだけ（責めない演出）
- 段階ヒントは**手帳の付箋**として1枚ずつ貼られていく

### 3-4. QR スキャン
- カメラ映像は今のまま（React 側）。枠だけ「望遠鏡のレンズ」風にする
- 読めた瞬間に Unity 側へ通知し、**レンズの先で宝箱がキラッと光る**カットを入れてから宝箱画面へ

### 3-5. 鍵のかかった宝箱の謎（いちばん力を入れる場面）
- 3D の宝箱が画面中央。**指で回して眺められる**。錠前は宝ごとにデザインが違う（貝殻の錠、流木の錠…）
- タップで錠前にカメラが寄り、問題文が錠前の札に浮かぶ → 下から回答欄（入力は React の input）
- 正解：鍵が回る → カチッ → フタが少し浮いて隙間から金色の光 → 一気に開く → 獲得画面へ
- 不正解：錠前が小さく弾かれる＋鈍い金属音

### 3-6. お宝獲得
- 開いた宝箱から**お宝の 3D モデル**がせり上がり、台座の上でゆっくり回転。背景に光の筋と舞う砂粒
- お宝 8 種それぞれに専用モデルと小さな演出：

| お宝 | 演出 |
| --- | --- |
| 貝殻の羅針盤 | 針がふらついてから北をぴたりと指す |
| 流木の鍵 | 木目に沿って光が走る |
| 潮騒の石碑 | 表面に波紋、波の音が鳴る |
| 星砂の小瓶 | 瓶の中の砂が星のように瞬く（夜は特に明るい） |
| 人魚のうろこ | 傾けると七色に変わる（端末の傾きに反応） |
| 灯台の古地図 | 破れた地図が広がり、灯台の光が一周する |
| 空色のビー玉 | 中に空と雲が流れる |
| 展望台の鈴 | 揺れて鳴る。音の輪が広がる |

- 「エリア ◯/◯・全体 ◯/◯」の数字は、宝が棚に飛んでいき**棚の空きが1つ埋まる**ことで見せる

### 3-7. コレクション
- 一覧カードの代わりに**木の飾り棚**（エリアごとに1段）。獲得したお宝が並び、未獲得は布がかかった影だけ
- お宝をタップすると取り出して回転表示（獲得画面と同じモデルを再利用）

### 3-8. クリア証明（スクショ対策と演出を両立）
- 規定数を集めた瞬間：飾り棚が光り、**「挑戦状」の封筒が戻ってきて、中から「達成状」が出てくる**
- 証明画面は達成状の上に受取用 QR。今の「動く時計と光のアニメーション」を、**ゆっくり回る金の封蝋と、紙の上を流れる光**に置き換える（スクショでは動きが止まるので、受付で見分けやすいまま）
- QR 自体は読み取り精度のため、装飾をかぶせず白地にはっきり表示

## 4. 技術・軽さの目標（スマホ WebGL）

| 項目 | 目標 |
| --- | --- |
| Unity バージョン | 6.3 LTS、URP（モバイル向け設定） |
| 初回ダウンロード | Brotli で 8MB 以内（お宝モデルは Addressables で後から読む） |
| 描画 | 光はベイク（リアルタイムの影なし）、ポストエフェクトは被写界深度とブルームだけ。テクスチャは ASTC |
| 1 場面のポリゴン | 3 万三角形以内、ドローコール 60 以内 |
| フレームレート | 30fps 固定（屋外でのバッテリー消費を抑える） |
| 低性能端末 | 起動時に計測し、遅ければ被写界深度・粒子を切る。それでも重ければ今の 2D 画面のまま遊べるようにする（**Unity が動かなくてもゲームは進められる**ことを守る） |
| React との連携 | React → Unity：画面遷移・状態（`locked/located/found/acquired`）・時間帯を送る。Unity → React：「宝箱をタップした」「演出が終わった」を返す。正解判定は今どおり Supabase の RPC だけ |

---

## 5. 進め方（案）

1. **宝箱を開ける場面だけ**先に作る（宝箱1種＋お宝1種＋鍵が開く演出）。ここが一番「グラフィックが良くなった」と感じる場所なので、まず実機の iPhone Safari で重さと見た目を確認
2. 獲得画面とお宝 8 種のモデル
3. タイトルと砂浜のジオラマ
4. 王子ヶ岳・たまの湯のジオラマ、コレクション棚、クリア証明

## 6. 決めてほしいこと

- 方式：**C（ハイブリッド）**で進めてよいか（A／B にしたい理由があれば教えてください）
- 方向性：**案1（瀬戸内ジオラマ）＋案2の紙の UI** でよいか
- ジオラマは実在の場所に寄せる度合い（地元の人が見て分かる程度の再現か、雰囲気だけか）
