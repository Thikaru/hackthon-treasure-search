## 修正1：謎の流れを「宝の道標」と「鍵のかかった宝箱の謎」に変更（2026-10-17）

### 背景（修正前の課題）

- 地図にはお宝がすべて表示されず、謎を1つ解くたびに1つずつ追加される。
- 次に挑戦できる謎も1問ずつしか出ないため、全体像が分からない。

### 修正後の流れ

お宝1つにつき、次の4ステップで獲得します。

1. **宝の道標**（旧：場所の謎）を解く
   - すべての「宝の道標」は、最初から一覧で確認・挑戦できる。
2. 正解すると、**その場所のヒント**が表示される
   - ヒントは「場所の画像」と「場所の説明」。どちらも任意入力で、片方だけ・両方なしでもよい。
3. 現地へ行き、**QRコードを読む**（または6桁コード）
   - 読み込んだお宝の場所が、地図に表示される。
4. **鍵のかかった宝箱の謎**（旧：獲得の謎）を解く
   - 鍵のかかった宝箱の画像が表示される。
   - 宝箱をタップすると、問題文と回答欄が表示される。
   - QRを読んだ後は、地図の宝箱から**どこからでも回答できる**（現地にいなくてよい）。

宝の道標を解かずに QR を見つけた場合も、従来どおりそのまま宝箱の謎へ進めます。

### 状態と表示名

| 状態 | 修正前の表示 | 修正後の表示 | 地図のピン |
| --- | --- | --- | --- |
| `locked` | 未解決 | 未解決 | 表示しない |
| `located` | 場所判明 | 道標クリア | 表示しない（場所はヒントの画像・説明で探す） |
| `found` | 発見 | 宝箱発見 | 表示する（朱色の宝箱） |
| `acquired` | 獲得 | 獲得 | 表示する（コバルト） |

### 画面の変更

| 画面 | 変更内容 |
| --- | --- |
| ホーム（地図） | 地図のピンは QR を読んだお宝（宝箱発見・獲得）だけ。下部カードに、表示中エリアの「宝の道標」を全問並べ、どれからでも挑戦できる。「すべての道標を見る」で一覧へ |
| 宝の道標一覧（新規 `#/guideposts`） | 全エリアの宝の道標を、問題文つきで一覧表示。状態（未解決／道標クリア／宝箱発見／獲得）が分かる |
| 宝の道標（`#/puzzle/:id`） | 画面名を「宝の道標」に変更。正解後に場所の画像と説明を表示（登録があるものだけ） |
| 鍵のかかった宝箱の謎（`#/found/:id`） | 鍵のかかった宝箱の画像を表示。タップすると問題文と回答欄が開く |
| コレクション・ヘルプ・運営画面 | 名称を「宝の道標」「鍵のかかった宝箱の謎」に統一 |

### データの変更（Supabase）

| 対象 | 変更 |
| --- | --- |
| `private.treasure_secrets.place_image_url` | **追加**。場所ヒントの画像URL（任意） |
| `private.treasure_secrets.place_hint` | 場所ヒントの説明（任意。空欄可）。従来どおり |
| `public.get_my_state()` | 道標クリア以降のお宝について、場所ヒントを `{ text, image_url }` の形で返す |

- 画像は道標に正解した人にだけ URL を返します。Supabase Storage に置く場合は、推測されにくいファイル名で公開バケットに置く想定です。
- 適用用の SQL は `supabase/migrations/002_guidepost.sql`（`schema.sql` にも反映済み）。

### 仮置きした前提

- 「宝の道標を全て確認できる」は、全問を一覧で見られて、どれからでも挑戦できることと解釈しています。
- 宝箱の画像はアプリ内のイラストを使います。お宝ごとに差し替えたい場合は別途対応します。

## 修正2：宝の道標の表示方法を「1つずつ」と「全問」で切り替え（2026-10-17）

### 内容

修正1では宝の道標を常に全問表示していました。これを、**1つずつ表示を初期設定**にし、運営画面で全問表示と切り替えられるようにします。

| 表示方法 | 設定値 | 参加者に見える道標 |
| --- | --- | --- |
| 1つずつ表示（初期設定） | `sequential` | エリアごとに、クリア済みの道標＋並び順で次の1問。残りは「ほかに N 問の宝の道標が眠っています」と件数だけ表示 |
| 全問表示 | `all` | 最初からすべての道標（修正1と同じ） |

- 並び順は `public.treasures.sort` です。エリアごとに独立して進みます（砂浜と観光名所を並行して進められます）。
- 1つずつ表示でも、QR を先に見つけたお宝は、従来どおり宝箱の謎へ進めます（その道標も一覧に表示されます）。
- 1つずつ表示のとき、まだ現れていない道標にはサーバー側でも回答できません（URL を直接開いても「まだ眠っています」と表示）。

### 運営画面

- **お宝・謎**（`#/admin/treasures`）の上部に「宝の道標の表示方法」を追加。ラジオボタンで切り替えると、その場で保存されます。
- 参加者の画面には、次に開いたとき（再読み込み時）から反映されます。

### データの変更（Supabase）

| 対象 | 変更 |
| --- | --- |
| `public.settings` の `guidepost_mode` | **追加**。`sequential`（初期値）／`all` |
| `private.guidepost_open(uid, treasure)` | **追加**。その参加者に道標が見えているかを判定 |
| `public.submit_answer` | 1つずつ表示で、まだ見えていない道標への回答を `guidepost_hidden` で拒否 |
| `public.staff_set_setting(pin, key, value)` | **追加**。運営PIN付きで設定を変更（今は `guidepost_mode` だけ許可） |

適用用の SQL は `supabase/migrations/003_guidepost_mode.sql`（`schema.sql`・`seed.sql` にも反映済み）。

## 修正3：次の宝の道標が現れる条件を「お宝の獲得」に変更・ホーム画面の整理（2026-10-17）

### 内容

- 1つずつ表示のとき、次の道標が現れる条件を **前の道標のお宝を獲得したとき** に変更しました（修正2では前の道標を解いたとき）。
- ホーム下部のシートには、いま挑戦中の道標を1問だけ表示します。見出し・「すべての道標を見る」リンク・説明文、上部の進捗バーは削除し、地図を広く表示します。
- シートはハンドルのタップ・上下ドラッグで上げ下げできます。表示内容が変わるときは、前の内容が下がってから次の内容が下から出てきます。
- 観光名所A・Bのエリア名を「王子ヶ岳」「たまの湯」に変更しました（`seed.sql`）。

### データの変更（Supabase）

| 対象 | 変更 |
| --- | --- |
| `private.guidepost_open(uid, treasure)` | 前の道標が「獲得済み」かどうかで判定するように変更 |
| `public.areas` の `spotA`・`spotB` | 名前を「王子ヶ岳」「たまの湯」に変更（`seed.sql` を再実行するか、個別に update） |

適用用の SQL は `supabase/migrations/004_guidepost_unlock_by_acquire.sql`（`schema.sql` にも反映済み）。

## 修正4：グラフィック刷新・Unity 化（unity ブランチ、2026-10-17）

`main` とは別の `unity` ブランチで進めています。デザイン案は `design/mockups/`（昼・夕方・夜 × 7画面）。

### 見た目

- トップ画面の「実写 × 時間帯」を全画面に広げました。どの画面でも、その時間帯の写真（昼＝砂浜、夕方＝王子ヶ岳の夕日、夜＝瀬戸大橋の夜景）をぼかして背景に敷きます。
- 前面は「すりガラス」と「生成りの紙（冒険手帳）」の2素材。差し色は昼＝コバルト、夕方＝茜と金、夜＝金の灯り。
- 宝の道標は木の立て札、ヒントは手帳の付箋、コレクションは木の飾り棚、クリア証明は「達成状」と回る封蝋。
- 時間帯の判定は従来どおり `useTimeOfDay`（`?tod=day|dusk|night` で固定可）。

### Unity

- 「鍵のかかった宝箱」と「お宝獲得」の場面を Unity（WebGL）の 3D で描きます。宝箱は指でなぞると回り、正解すると錠前が外れてフタが開き、光とともにお宝がせり上がります。
- Unity は Web 版に埋め込み、背景を透かして重ねます。QR 読み取り・地図・入力・Supabase は従来どおり Web 版が担当します。
- WebGL2 が使えない端末・読み込みに失敗した場合は SVG の宝箱で同じ流れを遊べます。
- ビルド手順は `unity/README.md`。

### 地図

- 砂浜エリアの地図を OpenStreetMap（Leaflet）から Google マップに変更しました。
- `VITE_GOOGLE_MAPS_API_KEY` がない場合は、鍵のいらない埋め込み地図を使い、宝箱ピン・現在地は地図の座標から計算して重ねます（ズーム・現在地はアプリのボタンで操作）。
- キーを設定すると Maps JavaScript API（指で動かせる地図・時間帯ごとの配色）に切り替わります。
- ピンの位置は従来と同じく `pin_x` / `pin_y` を渋川の範囲に比例で割り当てたものです（実際の設置場所の緯度経度で持つ改修は未対応）。

### 公開

- `unity` ブランチの版は https://aipapagames.com/shibukawa/ で公開しています（GitHub Pages の `main` 版とは別。データは同じ Supabase）。

### テスト用の合言葉

- unity ブランチはテスト版なので、宝の道標・鍵のかかった宝箱の謎とも「aaa」（全角・大文字も可）で正解になります。
- 本番版と同じ Supabase を使っているため、サーバーの正解データは変えず、**その端末の中だけ**で進んだことにします（localStorage に保存）。サーバーの記録・運営画面の集計・クリア証明の発行には反映されません。ログアウトすると消えます。
- 実装は `src/lib/game.tsx` の `TEST_PASS`。本番に入れるときは外してください。

### 開発用

- `npm run dev` で開き、URL に `?demo=1`（遊んでいる途中）／`?demo=clear`（クリア後）を付けると、Supabase に触れずにデモデータで全画面を確認できます（本番ビルドでは無効）。
