# 浜辺の宝さがし 仕様書

宝探し × 謎解きの Web アプリ（スマホのブラウザで遊ぶ）の、実装済み仕様をまとめたものです。
対象は `main` ブランチの現在のコードと、Supabase に作成済みのデータベースです。

- 参加者用：https://thikaru.github.io/hackthon-treasure-search/
- 運営用：https://thikaru.github.io/hackthon-treasure-search/#/admin （運営PINでログイン。参加者画面からのリンクはなし）
- リポジトリ：https://github.com/Thikaru/hackthon-treasure-search

> 運営PIN・正解・QRトークンは公開リポジトリには書きません。Supabase の `private` スキーマで管理しています。

---

## 1. ゲームの流れ

お宝1つにつき、謎を2回解くと獲得です。規定数（初期値 6 / 8 個）を集めるとクリアになります。

1. **場所の謎**を解く → お宝の場所ヒントが表示され、地図にピンが出る
2. 現地でポールの **QRコード** を読む（読めないときは QR 下の **6桁コード**）→「発見」
3. **獲得の謎**（ポールの札の合言葉など、現地でしか分からない答え）を解く →「獲得」
4. 規定数に達すると **クリア証明** が表示される → 受付でスタッフに見せて景品と交換

場所の謎を解かずに偶然 QR を見つけた場合も、そのまま「発見」になり獲得の謎へ進めます。

### お宝の状態

| 状態 | 表示名 | なるタイミング |
| --- | --- | --- |
| `locked` | 未解決 | 初期状態 |
| `located` | 場所判明 | 場所の謎に正解 |
| `found` | 発見 | QR（または6桁コード）を照合 |
| `acquired` | 獲得 | 獲得の謎に正解（`found` のときだけ可能） |

状態は前にしか進みません。獲得済みのお宝の QR を再度読むと、獲得画面を表示します。

## 2. 画面

ルーティングはハッシュ方式（`/#/...`）です。参加者画面はスマホ幅（最大 480px）で表示します。

### 2.1 参加者画面

下部タブは **ホーム（地図）／スキャン／お宝** の3つです。お宝タブはコレクションとクリア証明を切り替えて使います。

| パス | 画面 | 主な内容 |
| --- | --- | --- |
| `#/` | タイトル | ゲーム名、「はじめる」（未登録）／「つづきから」（登録済み）、遊び方へのリンク |
| `#/register` | 参加登録 | ニックネーム（12文字まで）、安全のための注意事項への同意 |
| `#/home` | ホーム（地図） | 獲得数とクリアまでの残り、エリア切替、地図とピン、次にやることのカード |
| `#/puzzle/:id` | 場所の謎 | 問題文、解答欄、段階ヒント、正解後に場所ヒントを表示 |
| `#/scan` | スキャン | カメラで QR 読み取り、6桁コードの手入力 |
| `#/t/:token` | QR の入口 | QR の URL。照合して「発見」にし、獲得の謎へ移動（未登録なら登録後に戻る） |
| `#/found/:id` | お宝発見・獲得の謎 | 獲得の謎の問題文、解答欄、段階ヒント |
| `#/got/:id` | 獲得 | お宝の名前と説明、エリア別と全体の獲得数 |
| `#/treasures` | お宝｜コレクション | エリア絞り込み、お宝カード一覧（状態つき） |
| `#/certificate` | お宝｜クリア証明 | クリア前は残り個数、クリア後は受取用 QR・現在時刻・ニックネーム・参加者No |
| `#/help` | 遊び方・ヘルプ | ルール、注意事項、引き継ぎコードの表示と復元、ログアウト |

#### 地図

- **砂浜エリア**：OpenStreetMap の実地図（Leaflet）です。渋川海岸（岡山県玉野市）周辺に表示範囲を固定しています。
  - 範囲外へのパン・ズームアウトはできません。
  - 地図をタップすると、自分用の目印ピンを1本立てられます（端末内だけで保存されません）。
  - お宝のピン位置は、`treasures.pin_x` / `pin_y`（イラスト地図用の座標 0–390 / 110–460）を表示範囲の緯度経度に比例で割り当てています。実際の設置場所とは一致しないため、緯度経度で持つように改修が必要です（→ 7章）。
- **観光名所A・B**：仮のイラスト地図です。
- ピンは **場所が判明したお宝だけ** 表示します。色は「場所判明＝水色」「発見＝朱色」「獲得＝コバルト」です。
- 車が必要なエリア（`areas.needs_car`）では「車での移動がおすすめ」と表示します。

#### クリア証明（スクリーンショット対策）

- 受取用 QR の中身は `TKNZ2|<トークン>` です。トークンはサーバーが発行します。
- 30秒ごとに新しいトークンに切り替わり、各トークンは60秒（`settings.certificate_ttl_sec`）で失効します。
- 画面には動く時計と光のアニメーションを表示します。
- 受取済みになると、QR の代わりに「受取済み」と表示します。

### 2.2 運営画面（`#/admin`）

運営PIN でログインします。PIN はタブを閉じるまでブラウザ（sessionStorage）に保持し、運営用の関数を呼ぶたびにサーバーで照合します。

| パス | 画面 | 主な内容 |
| --- | --- | --- |
| `#/admin/dashboard` | ダッシュボード | 参加者数（本日分）、クリア人数、受取済み数、未受取のクリア者数、お宝ごとの場所判明・発見・獲得数。30秒ごとに自動更新 |
| `#/admin/redeem` | 景品受取 | 証明 QR をカメラで読む（または内容を貼り付け）→ 獲得数・クリア可否・受取状況を確認 →「受取済みにする」 |
| `#/admin/history` | 受取履歴 | 全受付の受取記録、CSV 保存、取り消し |
| `#/admin/players` | 参加者 | 一覧と検索、獲得数・状態、無効化／有効化 |
| `#/admin/treasures` | お宝・謎 | 問題文・ヒント数の一覧（編集は Supabase で行う） |
| `#/admin/qr` | QR印刷 | お宝ごとの QR と6桁コードを A4 に並べて印刷、QR の再発行 |

ダッシュボードでは、発見数が5以上で「発見→獲得」の割合が50%未満のお宝を、オレンジで強調します（謎の難易度見直しの目安）。

## 3. 技術構成

| 層 | 採用技術 |
| --- | --- |
| フロントエンド | React 19 + TypeScript + Vite、react-router（HashRouter） |
| 地図 | Leaflet / react-leaflet + OpenStreetMap タイル（砂浜）、SVG イラスト（観光名所） |
| QR 読み取り | `getUserMedia` のカメラ映像 + jsQR（iPhone の Safari でも動作） |
| QR 生成 | qrcode |
| DB・認証 | Supabase（PostgreSQL、匿名ログイン、RLS、RPC） |
| 配信 | GitHub Pages（`main` への push で GitHub Actions が自動ビルド・デプロイ） |

接続先（Project URL と publishable key）は `.env.production` に書いています。publishable key はブラウザに出してよい鍵で、データは RLS と RPC で保護しています。

### 主なファイル

| パス | 役割 |
| --- | --- |
| `src/lib/game.tsx` | コンテンツと自分の進捗を読み込むコンテキスト、参加者向け RPC の呼び出し |
| `src/lib/supabase.ts` | Supabase クライアント、エラーコードの日本語化 |
| `src/pages/` | 参加者画面 |
| `src/admin/` | 運営画面（`staff.ts` が PIN 付きで RPC を呼ぶ） |
| `src/components/` | 地図（`AreaMap.tsx` / `RealMap.tsx`）、QR スキャナ、解答フォーム、タブバーなど |
| `supabase/schema.sql` | テーブル・RLS・関数（何度実行しても安全） |
| `supabase/seed.sql` | 公開してよい初期データ（エリア・お宝・問題文・設定） |
| `supabase/secrets.example.sql` | 非公開データ（正解・QR・PIN）の投入ひな形 |
| `.github/workflows/deploy.yml` | GitHub Pages への自動デプロイ |

## 4. データ設計（Supabase）

### 4.1 公開スキーマ `public`

| テーブル | 内容 | 読み取り |
| --- | --- | --- |
| `settings` | `title` `subtitle` `clear_count` `prize_name` `reception_place` `contact` `certificate_ttl_sec` | 誰でも |
| `areas` | エリア（id, name, short_name, description, needs_car, sort） | 誰でも |
| `treasures` | お宝（no, area_id, name, description, pin_x, pin_y, 場所の謎と獲得の謎の問題文・段階ヒント, sort, active） | 誰でも（`active` のみ） |
| `players` | 参加者（id＝auth のユーザーID, player_no, nickname, transfer_code, status, created_at） | 本人のみ |
| `player_treasures` | 参加者×お宝の進捗（state, ヒント使用数, located_at / found_at / acquired_at） | 本人のみ |

### 4.2 非公開スキーマ `private`

ブラウザ（anon / authenticated）からは一切アクセスできません。読み書きはすべて下記の関数経由です。

| テーブル | 内容 |
| --- | --- |
| `config` | 運営PIN（key = `staff_pin`） |
| `treasure_secrets` | QR トークン、6桁コード、場所ヒント、場所の謎の正解（複数可）、獲得の謎の正解（複数可） |
| `answer_logs` | 解答・スキャンの履歴（正誤つき） |
| `certificate_tokens` | クリア証明の短命トークン |
| `redemptions` | 景品の受取記録（参加者ごとに1件まで） |
| `staff_attempts` | 運営PINの照合結果（ロック判定用） |

### 4.3 関数（RPC）

参加者向け（匿名ログインしたユーザーが呼ぶ）

| 関数 | 内容 |
| --- | --- |
| `register_player(nickname)` | 参加登録（ニックネームの更新も兼ねる） |
| `get_my_state()` | 自分のプロフィール、進捗、判明済みの場所ヒント、受取済みかどうか |
| `submit_answer(treasure, kind, answer)` | 場所の謎／獲得の謎の照合と状態の更新 |
| `use_hint(treasure, kind)` | 段階ヒントを1つ開ける |
| `scan_treasure(code)` | QR トークンまたは6桁コードを照合し「発見」にする |
| `issue_certificate()` | クリア済みならクリア証明トークンを発行 |
| `restore_player(code)` | 引き継ぎコードで、別端末の進捗を今の端末に移す |

運営向け（すべて運営PINが必要）

| 関数 | 内容 |
| --- | --- |
| `staff_login` | PIN の確認 |
| `staff_verify_certificate` / `staff_redeem` | 証明トークンの確認／受取済みにする |
| `staff_redemptions` / `staff_undo_redemption` | 受取履歴／取り消し |
| `staff_dashboard` | 集計 |
| `staff_players` / `staff_set_player_status` | 参加者一覧／無効化・有効化 |
| `staff_qr_codes` / `staff_reissue_qr` | QR 印刷用データ／QR の再発行 |

内部用（`private`）：`norm`（解答の正規化）、`setting_int`、`require_player`、`check_pin`

## 5. 判定ルールとセキュリティ

- **解答の照合はサーバー側だけ**で行います。正解はブラウザに送りません。
- 照合前に、全角／半角・カタカナ／ひらがな・大文字／小文字・空白の違いをそろえます（例：「アオ」「あお」「ｱｵ」は同じ）。正解は複数登録できます。
- **送信回数の制限**：解答とスキャンは、それぞれ1分あたり15回まで。
- **運営PINのロック**：10分間に20回失敗すると、しばらくログインできなくなります。
- **QR**：中身は `#/t/<推測できないトークン>` の URL です。紛失・流出時は運営画面から再発行でき、古い QR は無効になります。
- **受取**：1人1回まで。証明トークンが期限切れ、クリア未達、無効化された参加者の場合は受取にできません。
- **参加者の識別**：Supabase の匿名ログインです。メールアドレスなどの個人情報は取りません。
- **獲得の謎**：答えを現地の札・看板など現地でしか分からない情報にすることで、QR 画像を共有されても獲得できないようにしています。

## 6. 運用

### 内容の変え方（Supabase の Table Editor / SQL Editor）

| 変えたいもの | 場所 |
| --- | --- |
| 問題文・ヒント・お宝名・説明・ピン位置 | `public.treasures` |
| エリア | `public.areas` |
| クリア数・景品名・受付場所・問い合わせ先 | `public.settings` |
| 正解・場所ヒント | `private.treasure_secrets` |
| QR | 運営画面「QR印刷」の再発行（または `private.treasure_secrets`） |
| 運営PIN | `private.config`（key = `staff_pin`） |

### 新しい環境に構築する手順

1. Supabase でプロジェクトを作成（Tokyo リージョン推奨）
2. Authentication → Sign In / Providers → **Allow anonymous sign-ins** をオン
3. SQL Editor で `schema.sql` → `seed.sql` → 非公開データ（`secrets.example.sql` を元に作成）の順に実行
4. `.env.production` に Project URL と publishable key を記入
5. GitHub の Settings → Pages → Source を **GitHub Actions** にして `main` に push

## 7. 既知の課題・今後の対応

| 項目 | 内容 |
| --- | --- |
| サンプルデータ | 問題文・正解・景品名は動作確認用の仮データ。本番前に差し替える |
| 砂浜のピン位置 | イラスト用の座標を比例で割り当てているため、実際の設置場所と一致しない。`treasures` に緯度・経度の列を追加して直接指定する |
| 観光名所A・Bの地図 | 仮のイラスト。場所が決まったら実地図にする |
| 地図の目印ピン | 地図タップで立てるピンは保存されない（リロードで消える） |
| CAPTCHA | 匿名ログインの乱用対策として、Supabase の CAPTCHA 設定を推奨 |
| テストデータ | 動作確認用の参加者「テスト運営」が1件登録済み（運営画面の「参加者」から無効化できる） |
| 運営画面への入口 | 参加者画面からのリンクはなし（URL 直打ち）。必要なら控えめな入口を追加する |
| 多言語対応 | 未対応 |
